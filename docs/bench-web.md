> **文档状态**：本机工作台 `cr studio` 已完成 React SPA 重写，支持配置目录、三步稀疏矩阵编排、配置工具、同源 write-only Providers 管理、运行日志、停止与结果导出（只监听 `127.0.0.1`），详见 [README](../README.md) 与 [DESIGN.md](../DESIGN.md)。`cr results export/merge/rank` 已支持 `schema_version: 2`（兼容读取 v1）。下文的**静态公开榜单站点**（部署到静态托管、浏览 `results.json` 与浏览器本地导入/分享）仍在规划中，与 [路线思考](roadmap.md) 中的榜单口径讨论衔接。

## 用户流程

1. **打开站点**：加载随站部署的 `results.json`；没有默认数据时显示空榜单和导入入口。
2. **准备跑分**：在网页上选已有场次或填写新场次（题面 PDF、判题后端、所需的赛事 ID 或题号映射），再选 harness，填写模型、API 类型、`base_url`、推理档位、凭据环境变量名和可选输出目录。表单按所选 harness 和判题后端展示字段，支持复用已有配置。校验后下载 `cr` 所需的场次清单和 Agent 配置，并复制命令。用户按页面说明把配置和题面放到对应位置，在本机执行。
3. **查看自己的跑分**：本机的 `cr bench run` 结算后直接生成同格式的结果文件。用户从同一站点选择文件导入，浏览器本地校验并展示；不上传文件，不调用跑分服务。
4. **保存或分享**：页面将选中的结果下载为同格式 JSON，可再次导入。要更新所有访客看到的默认榜单，就用导出的文件替换静态站自带的数据并重新部署。浏览器导入不会修改公共榜单，也不会同步到其他设备。

首版不需要服务器或数据库，也不依赖浏览器持久化：刷新后重新加载默认数据，需要保留更改时先导出。

网页和 CLI 复用可在浏览器运行的配置校验；网页不生成 Codex 原生配置，不读取真实 API Key 或 OJ 登录凭据，也不假定能知道下载文件在磁盘上的绝对路径。相对路径和文件摆放方式在下载时明确提示。最终的文件、凭据和 Docker 预检，以及 harness 原生配置生成，都由本机 `cr` 完成。

## 跑分输入与结果是两种文件

- 网页生成的 `contest.json` 和 Agent TOML 是给本机 CLI 的输入，不是成绩文件，不会随榜单导出。
- `run.json` / `events.jsonl` 是 runner 的私有记录，供调试和回放；不作为 Web 输入，不打包部署。
- `results.json` 是唯一的 Web 交换格式：站点默认数据、本地评测产出、Web 导入和导出都用它。首版记录格式版本、场次和数据版本、评测协议、Agent 修订、运行 ID、结算状态及按题的提交时间和判定；不携带密钥、本机路径、模型原文、源码、私有判题材料或未经授权的题面。
- 导入只接受受支持的格式版本；同一 `run_id` 的重复数据去重，内容冲突明确提示、不静默覆盖。不同场次、数据版本或评测协议分榜；作废运行不计排名。浏览器中导入的成绩是自带数据，不代表站方认证；页面应区分随站数据与当前浏览器导入的数据。

首个验收用 mock 链路走通「网页表单 → 下载的配置能通过本地 CLI 预检 → 本机跑分 → 同一网站导入结果 → 查看、导出和重新导入」。没有用户导入时也能查看默认榜单，不必等真实 Codex 和 OJ 接入。
