# Bench 配置界面草案（已搁置）

已搁置的是独立配置站，不是配置功能。CLI 参数准备并入同一套 [静态 Web](bench-web.md)。以下保留为早期讨论记录，旧版输入格式不作为新接口。

这是给跑分者使用的**配置助手**，不是公开榜单，也不是浏览器版 runner。首版先减少手写配置的成本；CLI 仍负责预检、运行和记录，CI 可继续不用界面。

## 首版流程

1. **选场次和输出目录**：填已有的 `contest.json` 路径和可选的 `--out`。引用已有场次清单，不需要重复填写 PDF、判题文件及其摘要。输出目录留空时沿用 CLI 默认值。
2. **配置 Agent**：选择已支持的 harness，填写 `agent_id`、选择支持的模型快照。常用参数用表单，进阶参数折叠；有现成原生配置时可直接引用，不要求界面理解任意 harness 的配置格式。赛时、工具权限和沙盒策略只展示，不允许通过表单覆盖。
3. **检查并生成**：预览、复制或下载 `agent.json` 和需要的原生配置（如 `responses.toml`）。生成配套文件时保持相对路径；让用户指定实际保存位置或在命令模板中替换路径，不假设浏览器能读到本机保存路径。界面不执行命令。

浏览器只检查字段和组合是否符合契约。文件是否存在、摘要是否匹配、Docker 是否可用、模型凭据是否已设置，都由 CLI 在本机预检。界面只显示所需的环境变量名，不接收 Key，不上传题面、答案或日志。

以现有 `problems.pdf` 和 Codex `config.toml` 为例，实际填写的是场次清单路径、harness 类型及版本、Agent ID、原生配置路径和可选输出目录。见 [Codex 填写示例](bench-codex-example.md)；Codex 接入尚待验证。

## 实现边界

- 配置助手可用 Astro 静态壳加 TypeScript 表单，作为独立的本地页面（计划放在 `config-ui/`）。不需要后端和数据库，不打包到公开榜单。公开 `web/` 仍只消费发布后的结果 JSON。
- 外层配置与内置适配器的字段校验，复用 runner 的浏览器兼容 schema 或由同一契约生成，不把 Docker、文件系统或 API 客户端打进前端。用同一份样例验证表单产物能通过 CLI 预检；不为未来适配器先做通用动态表单框架。
- 如果后来需要一键运行、取消或看进度，再评估独立的本地控制台。它使用同一个 runner，不接受任意 shell 命令，不并入公开站。首版不做浏览器启动 Docker、后台任务或在线跑分。
